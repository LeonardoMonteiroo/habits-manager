# habits-manager

Habit tracker. You create habits for chosen weekdays, check them off each day, and see the year so far as a grid where each day is shaded by the share of its habits completed.

This repository holds the API (`server/`) and the web client (`web/`). The mobile client (React Native with Expo) lives in a separate repository, [mobile-habits-manager](https://github.com/LeonardoMonteiroo/mobile-habits-manager), and is linked here as the git submodule `NLW-Setup-Mobile` (the earlier name of that repository).

The interface text is in Portuguese.

## Features

API (`server/src/routes.ts`):

| Method | Path | Purpose |
| --- | --- | --- |
| POST | `/habits` | Create a habit from a `title` and `weekDays` (0 = Sunday to 6 = Saturday). |
| GET | `/day?date=` | Return the habits available on that date and the ids of the ones completed. |
| PATCH | `/habits/:id/toggle` | Mark or unmark a habit as completed for today. |
| GET | `/summary` | For every recorded day, return the number of completed and available habits. |

Web client (`web/src`):

- Year-to-date grid with one square per day, shaded by completion percentage and padded with disabled squares up to 18 weeks.
- Clicking a day opens a popover with a progress bar and the checklist of that day's habits. Past days are read-only.
- "New habit" dialog with a title field and weekday checkboxes.

## Design notes

- Four tables (`server/prisma/schema.prisma`): `habits`, `habit_week_days`, `days` and `day_habits`. Unique constraints on `(habit_id, week_day)`, `date` and `(day_id, habit_id)` keep one schedule entry per weekday and one completion per habit per day. A `days` row is created the first time a habit is toggled on that date.
- A habit counts as available on a date if it was created on or before that date and is scheduled for that weekday. `GET /summary` computes this for all days in a single raw SQL query (`prisma.$queryRaw`) using SQLite `strftime('%w', ...)`.
- Request bodies, params and query strings are parsed with Zod; `GET /day` coerces `date` with `z.coerce.date()`.
- The schema diagram is generated by `prisma-erd-generator` into [`server/prisma/ERD.svg`](server/prisma/ERD.svg).

## Running locally

Requirements: Node.js and npm.

API:

```bash
cd server
npm install

# There is no .env.example. Prisma reads DATABASE_URL; the repo includes server/prisma/dev.db
echo 'DATABASE_URL="file:./dev.db"' > .env

npx prisma migrate dev   # apply migrations
npx prisma db seed       # optional: insert sample habits (prisma/seed.ts)

npm run dev              # http://localhost:3333
```

Web client:

```bash
cd web
npm install
npm run dev
```

The web client calls the API at `http://localhost:3333` (set in `web/src/lib/axios.ts`). Other scripts: `npm run build` and `npm run preview`.

Mobile client: clone this repository with `git clone --recurse-submodules`, or run `git submodule update --init` in an existing clone, or clone [mobile-habits-manager](https://github.com/LeonardoMonteiroo/mobile-habits-manager) directly. Its API address is set in its own `src/lib/axios.ts`.
